// THE UNGLAMOROUS HALF

This is the part that eats people's weeks, and the part a generic bidder cannot write. Each row is a real incident on a real box, with the fix that stuck.

What you'd sayWhat is actually happening
"The server keeps restarting / my model disappears"Your health-check timeout sits inside the cold-load band. Cold load was 62 s and over 300 s under memory pressure; the timeout was lower, so loads get killed, retried, and compound. Timeouts are arithmetic.
"It worked until I added the second GPU"HIP index renumbering after boot silently repoints the model at the wrong card. Pin by UUID, never by index.
"Broke after a system update"ROCm userspace versus kernel version roulette. The fix is a side-by-side userspace per model, not downgrading your distro.
"It throttles / shuts down under load"A passively-cooled server card with no fan interface. More case airflow made one of mine 4 °C worse; the fix was a sealed duct.
"The math says it should fit"The KV cache isn't quantized. -ctk q8_0 -ctv q8_0 is what stops a big context and a big model being enemies.
"--offload-to-cpu and now the machine OOMs"That flag loads the whole model into system RAM first; it does not stream from disk. On a 32 GB box the ceiling is around Q6_K.
"It's slow"No speculative decode. The MTP head on modern GGUFs gave me 92% draft acceptance — the single biggest lever, and it is a llama.cpp feature, not a CUDA kernel.
"AMD can't do AI"True in 2023. Today it is a wrong build target — a CMAKE_HIP_ARCHITECTURES mismatch fails silently — or a stale PyTorch/ROCm pairing.
